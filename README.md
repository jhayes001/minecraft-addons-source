# Havana's Minecraft Add-ons

Custom Minecraft Bedrock add-ons made for Havana's iPad worlds.
Each add-on is a **behavior pack** (`_BP`: items, recipes, scripts) plus a
**resource pack** (`_RP`: textures, names, particles). Activate the behavior
pack in a world and its resource pack turns on with it.

## Building the .mcaddon files

```
./build.sh              # all add-ons -> dist/
./build.sh MazeWand     # just one
```

Get the `.mcaddon` onto the iPad (AirDrop, iCloud Drive, email), tap it in the
Files app, then activate it under **Behavior Packs** in the world's settings.
If a scripted feature doesn't work, turn on **Beta APIs** under Experiments.

## Making changes: the two rules

1. **Never change a `uuid`.** The UUIDs identify each pack. New UUIDs make
   Minecraft treat it as a different add-on.
2. **Bump the version on every change**, in *both* `manifest.json` files of
   that add-on (header, modules, and the dependency the BP has on its RP).
   Minecraft refuses to re-import a pack with the same version.

## Technical notes

- Scripts use `@minecraft/server` **1.19.0** (latest v1 stable) and
  `@minecraft/server-ui` **1.3.0**. Moving to the v2 API would need code changes.
- `min_engine_version` is 1.21.50.
- Saved data uses dynamic properties: `rainbow:got_sword`, `maze:got_wand`,
  `maze:best_<Level>`, `house:got_blueprint`, `quest:got_bell`, `quest:data` (on players) and
  `quest:team` (on the world). Keep these names so progress survives updates.
- The Maze Wand keeps active-maze info in memory only, so hints and the timer
  don't work on a maze built before the world was reloaded.
- House Blueprint keeps its planner (floor plans, stairs, furniture) free of Minecraft API calls so it
  can be tested in Node: everything between `const GAP` and the `MINECRAFT SIDE` banner runs standalone.
  Each run of 2,000 simulated houses checks that every room on every floor is reachable on foot and covered by a roof.
- Bed color lives in block-entity data that scripts can't set, so House Blueprint ships 16 tiny
  pre-made beds in `HouseBlueprint_BP/structures/house/` (one per color) and places/rotates the right one
  with `world.structureManager.place`. Item frames (with an item) and banner curtains work the same way
  (`frame_<item>`, `banner_<color>`). Regenerate all 42 with `python3 tools/make_structures.py addons/HouseBlueprint_BP/structures/house`.
  If structure placement fails, beds fall back to plain red beds and frames to empty frames. Paintings are entities;
  the script tries `spawnEntity("minecraft:painting")` and puts an item frame there instead if that fails (and tidies up
  any painting that pops off the wall).
- `tests/house_remove_test.cjs` runs the whole House Blueprint script in a fake world: builds a house over a tree,
  removes it, and checks the land is restored block-for-block (and the backup path if snapshots aren't available).
- Santa's Visit stores the tree (`santa:tree`), last visited night (`santa:lastNight`), players seen
  (`santa:players`) and unopened presents with their gifts (`santa:presents`) as world dynamic properties.
  The sleigh model and texture are generated by `tools/make_santa.py` (also renders a preview).
  `tests/santa_test.cjs` runs the script against a fake world: plant, night flight, named presents,
  unwrapping, sleeping through the night, breaking presents, removing the tree.
- Gifts can't be put inside bundles yet (filling a bundle needs experimental script APIs), so bundles are
  one of the possible gifts instead.
- Pip is a vanilla `minecraft:villager_v2` with the `quest_keeper` tag; his trade
  screen is cancelled and replaced by the quest menu.
- Fairy Friends: all models and textures (fairy geometry, 9 color textures, egg, mushroom house and its
  lit version, item icon, dust sparkle) are generated by `tools/make_fairy.py addons/FairyFriends_RP [preview.png]`.
  The fairy is modeled at double size and shrunk with `minecraft:scale` 0.3; its color is the entity
  `variant` (0-8, set by events `fairy:color_N`) and girl/boy is `mark_variant` (events `fairy:girl` / `fairy:boy`),
  which the render controller uses to pick the texture and show the `girl` or `boy` bone. Wings use
  `entity_alphablend` so they're see-through. Movement is scripted (gravity off, teleported a little each tick). Each fairy picks an open-air spot
  1.6-3.8 blocks from its owner, flutters there slowly, hovers 2-6 seconds, then picks another; it hurries if
  you're more than 6 blocks away and blinks over if more than 20 blocks or a different dimension. Plans live in memory only.
  Saved data: on each fairy `fairy:owner`, `fairy:name`, `fairy:color`, `fairy:gender`, `fairy:state`
  (awake / flyingHome / asleep), `fairy:home`; on eggs `fairy:owner`, `fairy:age`; on the world `fairy:houses`
  (owner + location of each house); on players `fairy:got_starter`. A fairy sleeps in its owner's closest
  house within 64 blocks, or any house within 32 if its owner has none. Sleeping = invisibility effect +
  the block state `fairy:lit`. `tests/fairy_test.cjs` runs the whole day/night story against a fake world.
  Fairy light places an invisible `minecraft:light_block_14` (or `light_block` with `block_light_level` 14 on
  older versions) in the air block the fairy is in and moves it as the fairy moves; only into plain air. Light spots are
  saved in `fairy:lights` (world) and cleared on the next load if any were left behind. "Dark" is a heuristic (no stable
  light-level API in 1.19): no lit light source within 5 blocks that has a clear line to your head (walls block it), and
  night sky, or not the Overworld, or a roof over 4 of 5 spots around you. Checked every 0.5 s; turns on at the first dark
  reading, off after two bright readings in a row. Monster shoo checks every 0.5 s for
  `monster`-family mobs within 6 blocks of a player who has an awake fairy within 10 blocks; each mob at most every
  1.5 s; uses `applyKnockback`. Ender dragon and wither are skipped.
  Recipes: Fairy Egg = egg + glowstone dust + sugar (shapeless); Fairy House = 3 red mushrooms over
  planks, wooden door, planks.
- Alpha Dog: the dog model, its texture (black coat with a bit of shine, white chest splotch, dark brown eyes, pink tongue,
  orange collar with a rainbow tag; one ear up, one flopped over), the egg,
  the item icon, and both pack icons are generated by `tools/make_alpha_dog.py addons/AlphaDog_RP [preview.png]` (the
  preview lines up the egg and all four sizes on a one-block grid). One model; each size is a component group with
  `minecraft:scale` 0.45 / 0.7 / 1.0 / 2.2 (scale multiplies the collision box and seat positions too, so every size uses the
  same unscaled 0.7 x 1.2 hitbox and the name label sits just above the dog's head) and `minecraft:variant` 0-3, set by events `alphadog:stage_0`..`stage_3`. The render
  controller swaps the orange `collar` for `alpha_gear` (gold spiked collar + saddle) at variant 3; puppies get a bigger head
  (bone scale 1.35). Walking, head-turning, tail-wagging, panting, and the gait (head nods twice per stride like a horse, more with a rider
  via `query.has_rider`; trotting bounce; ear flaps) are client animations; the Alpha Dog's running sound is the `gallop` animation (ravager footstep thuds plus
  a wolf pant, as `sound_effects`), started by an animation controller when `query.ground_speed` > 1.5 and sped up with
  `anim_time_update` so faster running means faster thuds; barks and steps borrow the wolf
  sounds through the resource pack's `sounds.json`. The dog is a real mob with vanilla AI, not script-moved:
  `minecraft:is_tamed` + `tameable`, and the script calls `tame(player)` when it hatches (and retries every 5 s if the owner
  wasn't around), so `follow_owner` and `owner_hurt_by_target` work. It attacks `monster`-family mobs within 10 blocks
  that are within 8 blocks of a player (filter `distance_to_nearest_player`, so it guards you instead of hunting through caves), except creepers, endermen, zombified piglins, wardens, withers, the dragon, creakings, and ghasts. `damage_sensor` makes it
  unhurtable. `behavior.tempt` (priority 2, 16 blocks) on all the treats makes it come to anyone holding food. The Alpha size adds
  `rideable` (seat at y 0.82: seat positions are multiplied by `minecraft:scale`, so that's about 1.8 blocks up on a 2.2-scale dog; owner only, enforced in the script), `input_ground_controlled`,
  horse jumping, and `variable_max_auto_step` 1.0625 so it walks up whole blocks while ridden. Roaming is three component groups swapped by events: `roam_free` (follows once more than 8 blocks away;
  the default), `roam_close` (5 blocks), and `explore` (no following, long strolls). Every 60-150 s a free-roaming dog within 8 blocks of you
  has a 25% chance (`EXPLORE_CHANCE`) to explore for 12-25 s, never while you hold a treat or monsters are around; it stops when
  time's up, when it's 16+ blocks away, when you hold a treat, when a monster is within 10 blocks of you or 8 blocks of the dog,
  or when something hurts you (then it teleports to you if it's more than 14 blocks off). After a natural walk
  there's a 45% chance it brings a present when it's next within 4 blocks of you. More than 36 blocks away or in another
  dimension, it teleports to you, unless it's tied with a lead or being ridden. Growing to Alpha checks for a 3x3x3 open space
  first. One Alpha per player: the player property `alphadog:alpha` = {id, name, seen (world absolute time)} records it, so
  a parked (unloaded) Alpha still counts. It's refreshed every 5 s while that Alpha is loaded (an Alpha with no record, e.g.
  from before 1.0.5, is adopted), cleared by saying goodbye, and ignored once unseen for 3 in-game days of play
  (`ALPHA_GONE_AFTER`), so an Alpha removed some other way (pack switched off, a command) can't block you forever. Big Dogs
  past 30 points with another Alpha around stay Big Dogs and say so. Mischief: zoomies and chewing are short "busy" modes
  (`alphadog:mode` zoomies / chewing, ended by a memory-only timer, by danger, or by riding/leashing). Zoomies swap in the
  `alphadog:zoomies` group (random_stroll at 2.4x speed, 4 blocks, no following) for 4-6.5 s with `alphadog:dirt_kick`
  particles and barks: 1.2% per 5 s idle, 12% after a treat, 60% after growing, 35% when it comes running back; at least
  3 minutes apart; never while ridden. Chewing: every 5 s, with mischief on, chance by size (50/30/15/5%) to chew a natural
  log within 2 blocks (3 for the Alpha) at its feet or one up, if the tree has 3+ leaves (or nether wart blocks) above it and
  nothing built within 4 blocks (planks, torches, doors, glass, stairs, fences, stripped logs, any non-vanilla block, and so on,
  see `BUILT`). The `alphadog:chewing` group stops it and sets `mark_variant` 1, which plays the gnawing animation; after 3.5-5.5 s
  the log becomes its stripped version (same axis), 1-2 sticks drop, and 30% of the time it brings you a stick later
  (`alphadog:giftItem`). Because stripped logs count as "built," each tree gets one bite. 1-2 minutes between chews. Holding a
  treat or turning mischief off stops chewing without stripping. `alphadog:mischief` (on / off) on each dog. Sit and stay: `alphadog:sitting` (true / false) on the dog; event
  `alphadog:sit` swaps in the `alphadog:sitting` group (movement 0, no follow/stroll, `mark_variant` 2 = the sitting pose,
  `animation.alpha_dog.sit`, generated from `SIT_POSE` in the tool). Standing re-applies the roam group and the size group (for
  walking speed). A sitting dog is skipped by teleport-back, portals, exploring, zoomies, chewing, and come-to-help; it still bites
  monsters that come right up to it; riding a sitting Alpha makes it stand. Treat points: bone/raw meat/rotten flesh 1, cooked meat 2; sizes at 5, 15, 30 total (`GROW_AT`). Only the owner can
  feed, ride, or open the menu. Saved data: on each dog `alphadog:owner`, `alphadog:name`, `alphadog:stage`, `alphadog:food`,
  `alphadog:roam` (free / close), `alphadog:mode` (follow / explore), `alphadog:gift`; on eggs `alphadog:owner`,
  `alphadog:age`; on players `alphadog:got_egg`. Explore timers live in memory, so a dog that was exploring when the world
  closed just comes back. `tests/alpha_dog_test.cjs` runs the whole story against a fake world.
  Recipe: Alpha Dog Egg = egg + bone + black dye (or ink sac), shapeless.
- Unicorn Princess: the model (unicorn + princess as one entity, `unicorn:princess`), the four princess textures
  (variant 0-3: Rosalie pink, Violet purple, Marina aqua, Sunny yellow), the glitter sparkle, and both pack icons are generated by
  `tools/make_unicorn.py addons/UnicornPrincess_RP [preview.png]` (the preview shows all four princesses). The neck leans
  forward 30 degrees and the tail 20 degrees back as bone rotations in the model. Movement is scripted (gravity and collision
  off, teleported a little each tick, 2 blocks a second, half speed near someone who hasn't had a treasure yet), so the client
  animations run on `query.life_time`: `mark_variant` 0 = walking (`prance`: legs, body bob, nodding head, swaying princess, and
  `hooves`, which plays `mob.horse.soft` twice per stride), 1 = stopped (`wave`: princess waves and nods, unicorn paws the ground),
  set by events `unicorn:walk` / `unicorn:stop`; the princess is chosen with `unicorn:princess_N`. She follows the ground
  (the standing height closest to where she is, climbing at most 0.25 a tick); she walks through plants, leaves, snow layers
  and torches, and over water and lava. Pathfinding is local steering: a spot is walkable if it's at most 1 block up or 3 down,
  not on top of a fence/wall/pane/door/bed/cactus, and has 3 clear blocks above (`standAt`, cached per visit). Every 4 ticks
  she checks 2.8 blocks ahead (plus both sides of her body) and, if blocked, turns to the nearest open direction in 25 degree
  steps, keeping to one side while going around; she never takes a step onto an unwalkable spot (she turns in place instead),
  and if she's boxed in for 3 seconds she flies away over whatever is in the way. Doorways are too low for her, so she goes around houses.
  Leaving: 16 blocks after passing you (or after 2 minutes) she takes off (`takeOff`, event `unicorn:fly`, `mark_variant` 2 =
  the `fly` animation: nose up, legs galloping, tail streaming): 220 ticks of flying forward and up (speeds ramp to 0.22 and
  0.2 blocks a tick, about 40 blocks up), going straight up if a block is in the way, trailing a 7-band rainbow of glitter;
  then a sparkle and she's gone. No treasures while flying. If no player is within 96 blocks she just vanishes.
  Treasure time lasts 5 seconds: `glitterParty` every tick, plus the `unicorn:glitter_fountain` particle (24 sparkles shot
  up, tinted) and `rainbowBridge`/glitter rain around the player when the treasure drops. Schedule: world property `unicorn:plan` = {day, times, done}:
  each new day gets 1 or 2 (50/50) visit times between 1000 and 11000 (at least 3000 apart); a plan made late in the day
  gets one visit soon. Due visits wait for a player in the Overworld with open sky above (nothing solid in the 24 blocks over
  their head); after time 11500 with no visit yet that day, any Overworld player counts (she appears 12 blocks away if
  there's no ground to ride in on). Only started visits count, and the plan is saved, so reloading doesn't add visits. The
  fanfare is note.bit + note.flute + note.harp with note.bass under the long notes, played to everyone within 96 blocks.
  Gift range: 3 blocks flat distance and within 3 blocks up/down. A leftover unicorn (world closed mid-visit) is removed.
  `/scriptevent unicorn:visit` (cheats on) brings her right away without using up one of the day's visits.
  `tests/unicorn_test.cjs` runs five days in a fake world, plus walking up for a treasure, a hill, a roofed area, and a reload.
- Groundskeeper Elves: the elf model (with sickle, shovel, rake, and sack bones), the 4 outfit textures, the shed block
  model and its door-closed / door-open textures, the particles, and both pack icons are generated by
  `tools/make_groundskeeper.py addons/Groundskeepers_RP [preview.png]`. The elf is modeled at double size and shrunk with
  `minecraft:scale` 0.45 (about 0.9 blocks to the hat tip). Outfit is the entity `variant` (0-3, events `grounds:look_N`),
  the tool in hand is `skin_id` (0 none, 1 sickle, 2 shovel, 3 rake, 4 sack of clippings; events `grounds:tool_N`, shown and
  hidden with `part_visibility`), and the action is `mark_variant` (0 walk, 1 work, 2 wave; events `grounds:walk` / `work` /
  `wave`). The work animation depends on the tool (snip, dig, rake, toss). Movement is scripted (gravity and collision off,
  teleported up to 0.12 blocks a tick) with the same local steering as the unicorn: a spot is walkable if it's at most 1 up
  or 3 down and not on a fence, wall, door, water, lava, chest, composter, leaves, or the shed; if an elf can't get closer
  for 5 seconds (or is boxed in for 2.5) it does a "magic hop" with sparkles straight to where it was going.
  The shed block's `minecraft:cardinal_direction` is the way the door faces (the player places it facing them); the state
  `grounds:open` shows the open door while the elves are out. Schedule: one shift per shed per Minecraft day, starting at
  time 1000-11000 once someone is within 40 blocks (so the whole yard is loaded); a newly placed shed sends its elves out 5 seconds
  later if it's daytime. Shifts end when everything's done, at time 12300 (sunset), after 12 minutes, when everyone is more
  than 56 blocks away, or when the shed is broken. The yard is scanned 48 columns a tick (circle of radius 16, `YARD`, 4 blocks
  up and down from the shed). Targets: `short_grass` (and old `tallgrass`), the bottom half of `tall_grass` (and old
  `double_plant` grass), `snow_layer`, and `leaf_litter`, only when the block under it is natural ground or a path
  (`GROUND`), so snow on roofs and trees stays. Each elf takes the nearest unclaimed target (preferring the same job), works
  for about a second (1.8 s for grass, 2.4 s for tall grass: `WORK`), and clears just that one block (both halves of tall grass). Clippings: 30% (grass, leaves)
  or 50% (tall grass) chance each to raise the composter a level, like vanilla; at 7 it becomes 8 (bone meal ready). The
  elves carry up to 16 before a trip. With no composter in the yard they build one next to the shed (a side, never in front
  of the door) once per shed (`built` in the shed record); a full composter is only emptied if there's a chest (or barrel)
  within 2 blocks of the shed, and the bone meal and the snowballs (1 per snow layer, up to 64) go into it at the end of
  the shift. When nothing's left they take one more look at the yard, then go home. Saved data: world property
  `grounds:sheds` (each shed: place, door direction, owner, the two elves' names and outfits, jobs on/off,
  `lastDay`, `built`); on players `grounds:got_shed`. Shift state is memory only; elves left over after a reload are removed
  and the door closed. `/scriptevent grounds:shift` (cheats on) sends the nearest shed's elves out right away.
  `tests/groundskeeper_test.cjs` runs the whole story in a fake world (a yard with grass, tall grass, flowers, a snowy corner,
  leaf litter, a pond, a fence, and a house with snow on the roof), plus the menu, night, breaking the shed, and a reload.
  Recipe: Elf Shed = 3 oak slabs over oak planks, wooden door, oak planks, over oak planks, wooden hoe, oak planks.
